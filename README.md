# KsuConfigurator — конфигуратор считывателей «КСУ» (PROX, КС-MF-USB)

Замена оригинальной `KCY_UM.exe` (C++Builder 6, 2008 г.) для Windows 11.
.NET Framework 4.8, WinForms, C# 5, без SDK и NuGet.

Считыватель опознаётся по паре строк производителя/продукта
`PROX (www.prox.ru)` + `RFID reader` (без учёта регистра), а также как «кандидат» —
любое HID-устройство с feature-отчётом 128 байт.

---

## 1. Почему понадобилась замена

Оригинал импортирует `hid.dll` **по ординалам**. В Windows 11 таблица сдвинулась:
ординал 22 теперь `HidP_GetButtonCaps`, а `HidP_GetCaps` — 23. Из-за этого у старой
утилиты размеры отчётов читаются как нули и она не может работать с устройством.

Версия на C# вызывает всё **по именам**, поэтому от версии `hid.dll` не зависит.
Протокол восстановлен по дизассемблеру (`Pack` = `func_402DE0`, `UnPack` = `func_403044`)
и проверен на живом считывателе с прошивкой 12.0.

---

## 2. Сборка

```
build.cmd
```

Требуется только .NET Framework 4.x (компилятор
`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`). SDK, NuGet, Visual Studio
не нужны. Результат — `bin\KsuConfigurator.exe`, рядом копируется `KCY_UM.ini`.

Запуск без прав администратора (`asInvoker`), DPI-aware (PerMonitorV2).

Самопроверка без обращения к flash:

```
bin\KsuConfigurator.exe --selftest     -> bin\selftest.log
bin\KsuConfigurator.exe --dump         -> bin\dump.log
```

`--selftest` проверяет раскладку отчёта, round-trip Pack/UnPack, кодировку cp1251,
валидатор строк формата на всех реальных заготовках `KCY_UM.ini` и HID-стек
(перечисление + `HidP_GetCaps` по имени). Ожидаемый результат — `SELFTEST OK`.

`--dump` печатает все HID-интерфейсы и **читает** (не пишет!) текущий feature-отчёт
с разбором параметров. Flash при этом не затрагивается.

## 3. Порядок работы

1. **Снять перемычки** в корпусе считывателя. В режиме, заданном программой,
   перемычки должны быть сняты, иначе считыватель работает по «железной» настройке
   и программа может его не увидеть.
2. Подключить **только один** считыватель (иначе непонятно, с каким идёт работа).
3. Запустить `bin\KsuConfigurator.exe`. Поиск выполняется автоматически при открытии
   окна; повторно — кнопкой «Найти считыватели».
4. В таблице выбрать устройство (строка с признаком «свой»).
   При выборе приложение сразу **читает** текущий отчёт и показывает его в поле
   «Feature-отчёт 0x03» и версию прошивки. Это только чтение, flash не меняется.
5. Нажать **«Прочитать из устройства»** — поля формы заполнятся текущими значениями.
   **Перепишите текущую строку формата себе** — это ваш откат.
6. Отредактировать параметры.
7. **«Записать в устройство»** → откроется подтверждение с полным hex-дампом того,
   что уйдёт в считыватель. Проверить и подтвердить.
8. После записи приложение само перечитывает параметры для контроля.
9. Проверить результат на карте.

Перечитать заготовки из `KCY_UM.ini` — кнопка «Перечитать INI».
Кнопка «Добавить в [FStrings]» записывает текущую строку формата в `KCY_UM.ini`
следующим свободным ключом (секция `[FStrings]`, ключи «0»…«N», кодировка cp1251).

## 4. Параметры

| Поле | Смысл |
|---|---|
| Серийник | до 8 символов, cp1251, нуль-терминированный |
| Автоповтор 0,1 с | период повторной выдачи сообщения по USB HID Consumer Control; 0 — выключен; 0…255 |
| Интервал побудки 0,25 с | период опроса карты; 0…15 |
| Запретить вывод в RS232 | бит `0x10` |
| Запретить вывод на клавиатуру | бит `0x20` |
| Запретить будить компьютер из ждущего | бит `0x40` |
| Экономия потребления | бит `0x80`, опрос карты раз в 1 с |
| Версия прошивки | только чтение |
| Строка формата вывода | до 112 байт cp1251; счётчик под полем показывает занятые байты |

Кнопка «Слушать отчёты» читает input-отчёты (то, что считыватель выдаёт в момент
поднесения/удаления карты) и пишет их в лог как raw hex.

**Важно:** при включённом прослушивании чтение и запись параметров автоматически
останавливают его. Это обязательно: незавершённый `ReadFile` держит хэндл, и
`HidD_GetFeature`/`HidD_SetFeature` на том же хэндле не выполнятся, пока не придёт
отчёт — окно будет выглядеть зависшим.

## 5. Карта feature-отчёта 0x03 (128 байт)

| Смещение | Длина | Содержимое |
|---|---|---|
| `0x00` | 1 | ID отчёта, всегда `0x03` |
| `0x01`–`0x02` | 2 | версия прошивки (мл., ст.) — только чтение |
| `0x03`–`0x0A` | 8 | серийник считывателя, cp1251 |
| `0x0B` | 1 | автоповтор, шаг 0,1 с |
| `0x0C` | 1 | младший ниббл — интервал побудки (шаг 0,25 с); старший ниббл — флаги `0x10/0x20/0x40/0x80` |
| `0x0D`–`0x0F` | 3 | нули |
| `0x10`–`0x7F` | 112 | строка формата вывода, cp1251, нуль-терминированная |

Байты `0x01`–`0x02` при записи заполняются нулями — так же поступает оригинальный
`Pack` (`memset(отчёт, 0, 0x80)`), прошивка эти байты игнорирует. Поэтому в диалоге
подтверждения «версия: 0.0» — это нормально; после записи чтение снова покажет
реальную версию.

## 6. Строка формата вывода

Строка обрабатывается **самим считывателем** в момент поднесения карты, результат
выдаётся по всем разрешённым интерфейсам.

### 6.1. Спецсимволы

| Последовательность | Значение |
|---|---|
| `\t` | табуляция |
| `\r` | Enter (клавиатура) / возврат каретки |
| `\n` | Enter (клавиатура) / перевод строки |
| `\\` | символ `\` |
| `%%` | символ `%` |
| `%R` | сброс накопления контрольной суммы |

### 6.2. Данные: `%[a][b][c][d][e][f]g`

| Поле | Смысл |
|---|---|
| `a` | цифра 0…9 — начальная позиция в массиве байт (по умолчанию 0) |
| `b` | цифра 0…9 — количество байт **минус один** (по умолчанию вся длина массива) |
| `c` | способ вывода: `f` — десятичное число, `g` — строка с нуль-терминатором, `h` — строка заданной длины, `l` — не выводить (только для расчёта КС/CRC); по умолчанию — hex |
| `d` | реверс: `b` — бит-реверс каждого байта, `c` — обратный порядок байтов, `d` — то и другое |
| `.` | лидирующие нули: включить для десятичного, убрать для hex |
| `,` | рассчитать CRC и контрольную сумму для указанных значений |
| `g` | что выводим: `I` — серийник считывателя, `T` — тип карты, `U` — UID, `L` — длина кода, `K` — КС после последнего `%R`, `C` — CRC, `V` — вставка произвольного байта |

По умолчанию data-последовательность выводится в **hex с ведущими нулями**:
`%U` для карты `04 80 61 C2 DA 3E 58` печатает `048061C2DA3E58`.

Примеры из `KCY_UM.ini`:

```
DevID "%gI"; Card Type "%f.T"; Card UID Len %f.L bytes; Card UID "%U";
%R%001l,V%l,U%000l,V%000l,V%000l,V%C000000%U01
%20U %01f.U
%lW%03U
```

`%W` встречается в `KCY_UM.ini`, но в справке не описан — валидатор помечает его
предупреждением (не ошибкой), запись не блокирует.

### 6.3. Внутренний порядок байтов UID (важно)

Массив UID внутри прошивки проиндексирован **в обратном порядке** относительно того,
что печатает полный `%U`. Для карты, которая печатается как `04 80 61 C2 DA 3E 58`:

| индекс `a` | байт |
|---|---|
| 0 | `58` |
| 1 | `3E` |
| 2 | `DA` |
| 3 | `C2` |
| 4 | `61` |
| 5 | `80` |
| 6 | `04` |

Проверено на прошивке 12.0: строка `%10U%20U%30U%40U%50U%60U%00U` дала
`3EDAC261800458`, то есть `%00U` → `58` (последний байт печатаемого UID),
а `%60U` → `04` (первый). Отсюда любая перестановка байтов собирается
из одиночных вставок `%N0U`.

## 7. Пример: перестановка байтов UID

Задача: из `04 80 61 C2 DA 3E 58` получить `80 61 C2 DA 3E 58 04`
(первый байт переезжает в конец).

```
%50U%40U%30U%20U%10U%00U%60U
```

| фрагмент | индекс | байт UID | вывод |
|---|---|---|---|
| `%50U` | 5 | 80 | `80` |
| `%40U` | 4 | 61 | `61` |
| `%30U` | 3 | C2 | `C2` |
| `%20U` | 2 | DA | `DA` |
| `%10U` | 1 | 3E | `3E` |
| `%00U` | 0 | 58 | `58` |
| `%60U` | 6 | 04 | `04` |

Результат — `8061C2DA3E5804`. Длина строки 28 байт из 112 допустимых.

Реверс (`c`) здесь не подходит: он даёт зеркало `583EDA…`, а не сдвиг.

Пошагово:

1. «Прочитать из устройства», сохранить себе прежнюю строку формата.
2. Вставить строку выше в поле «Строка формата вывода» (при желании —
   «Добавить в [FStrings]», чтобы она осталась в `KCY_UM.ini`).
3. «Записать в устройство» → проверить hex-дамп: с `0x10` должно идти
   `25 35 30 55 25 34 30 55 25 33 30 55 …` → «Записать».
4. Курсор в Блокнот, поднести карту — ожидается `8061C2DA3E5804`.
5. «Прочитать из устройства» — строка должна вернуться из считывателя целиком.

Если нужен Enter в конце, добавьте `\r` после последней вставки.

## 8. Ограничения и предостережения

* **Ресурс flash — несколько десятков тысяч перезаписей.** Каждая запись параметров
  расходует цикл. Не гоняйте запись по кругу ради эксперимента: проверяйте чтением
  и поднесением карты.
* Строка из примера рассчитана на **7-байтовые UID** (NXP, первый байт `0x04`).
  Для 4-байтовых карт позиций 4–6 не существует, вывод будет другим. Универсальной
  строки «для всех карт» нет — под каждый тип карт нужна своя.
* Вывод на **клавиатуру**: гарантированы только цифры, `+ - * /`, Tab и Enter;
  латинские буквы и прочие символы зависят от текущей раскладки. По USB HID
  Consumer Control ограничений на символы нет. В шестнадцатеричном выводе
  буквы `A`–`F` — именно латинские.
* Запись блокируется, если валидатор нашёл ошибки в строке формата (неизвестный
  выводимый символ, висящий `%` или `\`, длина больше 112 байт cp1251).
  Предупреждения (например, `%W`) запись не блокируют.
* В списке HID-устройств часть интерфейсов помечена `[CreateFile: Отказано в доступе]` —
  это системные клавиатуры и служебные коллекции, к считывателю отношения не имеют.
* Программа работает только с параметрами; чтение карт она не эмулирует.
  «Слушать отчёты» показывает raw input-отчёты, а не разобранный номер карты.
